# TT League

Мобильная лига настольного тенниса без выбывания. Приложение: https://siblife54-dot.github.io/tt-league/

## Как пользоваться

1. Добавьте профили игроков, можно несколько имён через запятую.
2. Выберите 4–32 участников и начните турнир. Программа назначит случайные стартовые пары.
3. Введите счёт текущего матча. Переходы и новая пара появятся автоматически.
4. Завершите турнир по кнопке. Итоги автоматически остаются в истории.
5. «Скопировать для ChatGPT» выдаёт Markdown с результатами всех матчей и статистикой. JSON сохраняет всю базу для восстановления.
6. В истории можно удалить тестовый турнир. Его матчи, очки сезона и ачивки исчезнут из расчётов; профили сохранятся.

## Правила версии 1

Одна партия до 11, после 10:10 разница 2. Открытие: победитель Gold, проигравший Silver. При нечётном составе последний в сохранённой случайной жеребьёвке после открытия получает технический проход в Gold без очков.

После открытия победа поднимает на один уровень, поражение опускает; Gold — потолок, Bronze — нижний уровень. Очки за победу по уровню ДО матча: старт 2, Gold 3, Silver 2, Bronze 1. Поражение не отнимает очки.

Первым выбирается участник с меньшим числом матчей, затем — с большим ожиданием. Соперник: меньше матчей, ближе уровень, меньше повторов, дольше ожидание, жеребьёвка. В межуровневом матче каждый переходит относительно собственного прежнего уровня; очки победителю — за его прежний уровень.

Места: сумма турнирных очков, затем процент побед, средняя разница игровых очков за матч, затем сохранённая жеребьёвка. Очки сезона за места 1–8: 15, 10, 7, 5, 4, 3, 2, 1; с 9-го места — 0. Эти начальные настройки видны перед стартом. Число матчей может различаться.

Завершение доступно после стартовых матчей. Следующая предложенная пара при завершении не учитывается. Для ошибочного результата есть отмена последнего счёта; исправления давно сыгранных матчей с зависимыми переходами в первой версии не поддерживаются.

## Общая база и вход

Supabase хранит одну общую лигу. При каждом открытии сайта выбирается зритель или организатор. Организатор вводит общий пароль, без почты и регистрации. Supabase проверяет хэш и выдаёт временный сеанс на 12 часов; токен хранится только в памяти вкладки. В коде есть только публичные параметры проекта. Зрители могут читать результаты; запись идёт через серверную функцию, проверяющую сеанс и текущую версию данных.

Обновления проверяются каждые 5 секунд. При конфликте ввод не сохраняется поверх чужого результата: нужно обновить данные. Если нет связи, приложение не выдаёт локальную запись за успешное сохранение в облако. Интерфейс доступен из кэша, но для общей базы нужен интернет.

Удаление турнира убирает его матчи, рейтинг, титулы и достижения из расчётов. Профили остаются. Старые данные браузера не загружаются автоматически: организатор может перенести их кнопкой в истории. JSON-импорт заменяет общую лигу для всех устройств после явного подтверждения. Перед импортом предлагается скачивание копии; при доступном локальном хранилище сохраняется резерв перед заменой.

### Первичная установка

1. В отдельном проекте Supabase TT League открыть SQL Editor.
2. Вставить `supabase/shared-password.sql` и заменить `REPLACE_WITH_YOUR_LEAGUE_PASSWORD` в строке присвоения внизу файла на общий пароль (8+ символов, максимум 72 байта UTF-8). Для простого ввода используйте латинские буквы и цифры. Не сохраняйте заполненный паролем скрипт в GitHub.
3. Выполнить весь скрипт. Повторный запуск сохраняет турниры, меняет пароль и отзывает сеансы.
4. `cloud-config.js` содержит только URL и publishable key проекта. SQL создаёт публичное чтение и проверяемую запись. Supabase Auth не используется.
5. Проверить установку и только затем публиковать этот выпуск в main. Пока SQL не установлен, новая версия показывает сообщение о незавершённой настройке.

Для проверки SQL отдельно использовалась PGlite с pgcrypto: права зрителя, пароль, сеанс, запись, конфликт, выход, ограничение попыток и повторная установка. Проверка опубликованного Supabase обязательна после установки. Тесты `tests/cloud.test.js` проверяют HTTP-клиент с имитированными ответами; они не заменяют проверку реального сервера.

## Разработка и публикация

Статические HTML/CSS/JavaScript-модули, без сборки и внешних runtime-зависимостей. `domain.js` — чистые правила, `storage.js` — IndexedDB, `app.js` — интерфейс. `npm test` запускает тесты Node.js; `npm run check` проверяет синтаксис. Для локального просмотра: `python -m http.server 4173` из корня репозитория.

GitHub Pages: ветка `main`, каталог `/ (root)`. Все пути относительные, приложение работает в `/tt-league/`. При обновлении ресурсов меняйте версию кэша в `sw.js`. Не публикуйте резервные копии реальных турниров в репозитории.

## Выравнивание матчей

Обычная очередь отдаёт приоритет меньшему числу матчей, затем ожиданию. Соперник подбирается по числу игр, близости уровня, повторам и ожиданию.

После стартовых матчей кнопка «Выровнять» показывает ближайшую достижимую общую норму и число оставшихся встреч. Каждая пара сохраняет возможность закончить выравнивание. Достигшие нормы больше не играют. По окончании появляется выбор: завершить или продолжить турнир. Режим сохраняется в общей базе и допускает повторное включение. Старые результаты и порядок исторических матчей сохраняются. SQL обновлять не нужно.

Общая статистика в разделе «Рейтинг» и профилях: выигранные турниры, участие, матчи, победы, поражения, процент побед, набранные и пропущенные игровые очки и их разница. Считается из всех завершённых сохранённых турниров и пересчитывается после удаления.

## Telegram-комментатор

После старта турнира, каждого сохранённого счёта и завершения Supabase создаёт событие в закрытой очереди. Edge Function `tt-commentator` собирает проверенные факты, просит Cloud.ru написать короткую реплику и отправляет сообщение в Telegram. Счёт, имена, места и статистику формирует код; модель пишет только комментарий. Если Cloud.ru недоступен, отправляется шаблонная реплика, а турнир продолжает работать.

При отмене последнего счёта прежнее Telegram-сообщение помечается как отменённое. Исправленный результат приходит отдельным сообщением после повторного сохранения. Дубли блокируются уникальным ключом события и его статусом. При удалении турнира его закрытые записи комментариев удаляются вместе со статистикой; уже отправленные сообщения остаются в истории Telegram.

### Установка комментатора

1. Развернуть `supabase/functions/tt-commentator` со встроенной JWT-проверкой. Database Webhook передаёт публичный legacy `anon` JWT проекта, после чего функция принимает только UUID уже созданного события и повторно сверяет его в базе.
2. В Supabase → Edge Functions → Secrets добавить:
   - `CLOUDRU_API_KEY` — секретный ключ Foundation Models;
   - `CLOUDRU_BASE_URL` — `https://foundation-models.api.cloud.ru/v1`;
   - `CLOUDRU_MODEL` — `openai/gpt-5.4-mini`;
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `TELEGRAM_CHAT_ID` — ID группового чата, обычно отрицательное число.
3. В `supabase/commentator.sql` заменить `REPLACE_WITH_SUPABASE_ANON_KEY` на публичный legacy `anon` JWT проекта и выполнить файл целиком в SQL Editor проекта TT League. Скрипт сохраняет существующие турниры, добавляет закрытую очередь и обновляет `tt_write`, чтобы событие и результат матча записывались одной транзакцией.
4. Добавить бота в групповой чат. Для первого теста начать отдельный тестовый турнир, сохранить один счёт, проверить сообщение, отменить счёт и завершить турнир.

Секреты не записываются в GitHub. Пример названий находится в `supabase/functions/.env.example`; файл `supabase/functions/.env` исключён из Git.
